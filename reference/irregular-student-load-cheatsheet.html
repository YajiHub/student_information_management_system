Irregular Student Load Architecture

Enterprise RESTful API patterns for managing student unit loads and cross-section scheduling.

1. HTTP Status Code Matrix for Enrollment Failures

Scenario HTTP Status Error Message Format
Section full (active enrollments $\ge$ capacity) 400 Bad Request "Course offering section is at full capacity"
Term unit sum exceeds max_allowed_units 400 Bad Request "Enrollment exceeds maximum allowed units for this student (Attempted: X, Allowed: Y)"
Student already enrolled in offering 409 Conflict "Student is already enrolled in this course offering"
Missing or malformed payload fields 422 Unprocessable "Validation failed" with field error map
Non-admin user attempts enrollment 403 Forbidden "Forbidden resource"

2. Prisma Data Models

enum StudentType {
  REGULAR
  IRREGULAR
}

model Student {
  id                Int         @id @default(autoincrement())
  student_number    String      @unique
  student_type      StudentType @default(REGULAR)
  max_allowed_units Int         @default(24)
}

model Enrollment {
  id                 Int            @id @default(autoincrement())
  student_id         Int
  course_offering_id Int
  status             EnrollmentStatus @default(ENROLLED)

  @@unique([student_id, course_offering_id])
}

3. Common Administrative Filter Queries

  • GET /api/v1/students?student_type=IRREGULAR — Find all irregular students.
  • GET /api/v1/students?student_type=IRREGULAR&year_level=3 — Filter by year level.
  • GET /api/v1/students?search=santos&student_type=REGULAR — Search regular students.
